LinkCard Event Admin

On-site handbook

Event organisers and door staff

Who this handbook is for

  • Organiser：Owns the event. Can read the roster, settings and every door tool.
  • Door staff：Trusted to check people in and work the NFC desk, but cannot read the full roster.

How to use this handbook

  • Each section is one job. Follow the numbers and you have done that job.
  • The circled numbers on a picture match the table underneath it.
  • If your screen looks different, read that step's note first. The difference usually has a reason.
  • Anything marked as not yet available means a person has to handle it by hand for now.

How these screens were captured

Screens were captured in a phone-sized browser window (390 x 844 at 2x). Camera and NFC are phone hardware, so the app's own notices appear on those screens instead of a live view.

The phone app, or the laptop check-in desk?

This app's NFC writing has not been retired: it still works and still issues cards. The new "Web check-in desk" is a second route, not a replacement. From now on both routes exist on site at the same time, and picking the wrong one costs you a queue.

The rule in one line: if you have a laptop and a reader, use the laptop check-in desk; if you have only a phone, use this app.

What you have Which route The difference
Laptop + an ACR1555U reader + Chrome or EdgeWeb check-in desk (laptop)Scan the QR, press "Write this card"; the system builds the card URL, binds it and reads it back to verify
Only a phone (iPhone or Android), no readerThis app (phone NFC, Part 5, E1–E2)The phone is the reader; no extra hardware is involved
iPad, an Android tablet, Safari, FirefoxNeither route worksThe web route needs Web Bluetooth, which none of these provide; switch to one of the routes above

Never write the same card from both routes. Once one side has bound it, that is final; if you try both, one side succeeds and the other reports that the card already belongs to someone.

The full laptop procedure (connecting the reader before the doors open, the six reader states, the nine failure branches, the yellow "written but not registered" case, and the list of things not to do) lives in a separate book: "Web check-in desk — on-site operating manual" (LinkCard_Frontend/docs/handbook/web-checkin-desk-zh.md, in Chinese). This book does not repeat it; do not mix the two.

When you are doneThe result appears, then the screen returns to scanning after about 15 seconds, ready for the next person.

What you see：The running check-in total sits on top, with the scanning frame below.

1Running check-in total
2Aim the QR code at this frame

C1-2 Check that you are in scan mode.

What you see：Two tabs sit at the top: scan mode uses the camera, typing uses the keyboard.

1Currently using the camera
2Press here when the camera will not work

C1-3 Point the phone at the QR code. If the screen says the camera is unavailable, read the two options it offers.

What you see：Allow camera asks for permission again; switch to typing turns this into manual entry straight away. Neither sends the attendee back to the queue.

WhoDoor staff
WhenAfter every check-in.

Before you startYou have completed at least one lookup.
When you are doneYou know what to do next for every outcome.

C3-1 Outcome one: the ticket is valid and is now checked in.

What you see：A green Checked in headline. Let them through.

1Let them through

C3-2 Outcome two: this person was already checked in.

What you see：The headline says Already checked in. Do not wave them through again; ask whether they already entered.

1Not a new arrival, confirm first

C3-3 Outcome three: the ticket cannot be found.

What you see：The headline says Invalid registration. Check for a typo first, then ask for their original confirmation email.

1Do not let them through

C3-4 Outcome four: the connection is the problem.

What you see：The screen reports a network failure. That is not the same as an invalid ticket: the ticket may be fine. Verify by hand or switch networks, but do not treat it as fake.

1A network problem, not a ticket problem

Part 6: When things are not normal

F1 The token desk, and what to do when the network drops

WhoOrganiser
WhenAn attendee wants tokens, or the venue network is patchy.
What you wantKnow that the token desk lives on the web, and how to handle a connection problem.
Before you startYou are inside the event.
When you are doneYou will not hunt for token features in the app, and will not mistake a network problem for a fake ticket.

F1-1 Press Token in Quick actions.

What you see：The app explains that the token desk is web-first and this is only a doorway.

1The app does not host the full desk

F1-2 Press Open the desk on the web.

What you see：It opens the web console in your phone's browser, where the same account works.

1Top-ups and deductions happen on the web

F1-3 If check-in reports a network or server problem.

What you see：This is not the same as a registration not being found. The ticket may be fine: verify by hand or switch networks, but do not treat it as fake.

1When the network is patchy, switch to typing and retry

F1-4 For a duplicate or an exception you want to allow, press Request supervisor override.

What you see：This feature is not open yet. The screen states the backend is not ready, so let the person through by hand and keep a written record rather than changing data yourself.

1Not available yet, handle it by hand
