# 07 — Independent Verification of the LC-ADMP Parity Pack

**Status:** produced by an **independent review unit**. The author of `00`–`06` did **not** write this
file, and the pack's author did not review it before publication.
**Review date:** 2026-10-15 · **Loop:** LC-ADMP · **Review mode:** deep / strict / adversarial
**Scope:** all seven documents in this directory, re-measured against the five sibling repositories
**Unit:** 1 (no subagents dispatched, per the review spec)

This review tried to **falsify** the pack. Every number below was re-derived from the working trees;
every URL claim was re-fetched. Where a claim survives, it is marked as surviving. Where it does not,
the command and its real output are given so the author can reproduce the disagreement.

---

## Verdict

**`PASS WITH FINDINGS`**

The pack's central measurements reproduce, its recommendation is defensible, its sources exist, and
its own "Contradictions" section is unusually honest. I re-ran every command in `01-drift-audit.md`
and **19 of the 24 numeric cells reproduce exactly** — including the two figures the whole audit
turns on: 121 endpoints under `/api/v1/events` with the full 11-file per-route breakdown, and **0**
`@openapi` annotations in `src/events/`. All 13 cited URLs I fetched resolved and their attributed
quotes reproduced verbatim; the pivotal "Web NFC is not implemented in Safari" claim I independently
confirmed against MDN. The recommendation (Option B) is the right call on the evidence.

It is **not** a clean `PASS`, and it is not a `FAIL`, because three findings are _false as written_
rather than merely imprecise, and each one makes the situation look **better** than it is:

1. `01-drift-audit.md` §8 concludes there is "no shared package… only a duplicated token file". The
   `theme.ts` search was too narrow: the two Expo apps share **29 identically-named files**,
   including a ten-component `components/ui/*` kit, and one of them (`src/constants/config.ts`) has
   diverged **semantically** — Promoter fails closed when its API URL is missing, the Admin App
   silently falls back to production. This is a more dangerous divergence than the formatting
   difference the audit describes, and it contradicts `04`'s stated prerequisite for revisiting the
   monorepo option ("Today there are **zero** — only a duplicated token file").
2. §8 also states the `theme.ts` diff "is dominated by _formatting_". After normalising whitespace
   and quotes, seven semantic differences remain, including a **changed token value**
   (`tabBarHeight: 56` → `52`) and removed exports (`fontFamily`, `elevation`, the `theme` aggregate).
3. §D8 asserts "The App's genuine value is _door-side, sensor-driven, **offline-tolerant** work" —
   while `03-gap-matrix.md` A20 records offline check-in as **✗ on both surfaces** and `05` defers
   it as net-new. The audit's own summary claims a capability its own gap matrix says is absent, and
   the pack's own research (`02` §D2.1) calls offline check-in "a must-have feature for any event
   over 100 attendees".

A fourth High finding is an omission rather than an error: the App has a committed `ios/` Xcode
project (18 tracked files) and **no `expo-updates` dependency**, so EAS Update — which `06` Rule 6
and `05` P3-5 present as the release-cadence answer — is not merely unconfigured but unavailable
today, and the stated `runtimeVersion` bump rule is incomplete for a repo with native code checked in.

None of this changes the direction. All of it is fixable by editing specific sections, which is what
`PASS WITH FINDINGS` means here. **Round 1 of `strict` mode; repair is warranted, not abandonment.**
