## 8.5 我這輪自己犯的錯（誠實記錄）

- **一條「CI 會紅」的發現被自己的實測推翻。** 我判定固定下限 25 會讓單 repo 環境
  紅，`89d9d5d` 上實測是 `checked=26`、`ambiguous=3`——下限過關（餘裕 1），真正卡

  `ambiguous=12`（§8.4-5 的表）。教訓有兩個：**模擬 ≠ 實測**；而且**沒有標時點的
  量測值一定會跟別的量測值打架**——所以本檔每一個數字都標它量在哪個 SHA 上。
- **我自己引入的一個引用缺 repo 前綴，讓 `npm test` 紅了一次**（`342838f` 才修好）。
  機械閘門抓到我，不是我抓到它。
- **兩處 locator 寫錯**：`sessions-polls.routes.ts` 原本寫 `:33-44`（`bdc2f8d` 改成
  `:29-44`）；`04` 的
  `LinkCard_ExpressJS_Backend@src/events/services/EventWalletService.ts:43-51` 一度
  漏了 repo 前綴（`342838f`）。

**這批文件最大的風險不是判斷錯，是引用漂移。而閘門只擋得住「引用壞掉」——檔案消
失、行號超長、裸檔名解析不到；「引用漂移」它擋不住，只能靠人重讀。所以這兩件事
要分開講：機械的部分做到極致，剩下的部分不能假裝已經自動化了。**
