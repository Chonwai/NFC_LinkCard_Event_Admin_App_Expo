## 8.4 宣稱的效果做不到（最該看的一段）

### 1. CI 不會強迫你做判定

`scripts/check-parity-registry.mjs` 的 `checkWeb()` 在 Web repo 不存在時**直接
`return`**：不帶 `--require-web` 就只印一行 `SKIPPED`，然後 `exit 0`。CI 只
checkout 本 repo（`.github/workflows/ci.yml:46` 跑的是 `npm run check:parity`），
所以那條檢查在 CI 上永遠不執行。

規則本身是有牙齒的，我做了差分驗證：

```
# 在暫存的 App＋Web 複本上
node scripts/check-parity-registry.mjs --web ../LinkCard_Frontend --require-web   # 18/18, exit 0
mkdir -p "../LinkCard_Frontend/app/(event)/manage/[eventId]/fake-new-module"
printf 'export default function Page() { return null; }\n' > "../LinkCard_Frontend/app/(event)/manage/[eventId]/fake-new-module/page.tsx"
node scripts/check-parity-registry.mjs --web ../LinkCard_Frontend --require-web   # 19 頁／18 登記, exit 1
```

牙齒在，只是**在 CI 上不會被咬到**。今天在 CI 真正有效的只有「登記表與 App 檔案、
文件章節三者自身一致」這一半。

### 2. 後端契約閘門不在任何分支的 tip 上

### 5. 引用下限：上一輪的說法錯了，真正越線的是另一道門檻

引用天生無法唯一解析」。判定因此不變。
