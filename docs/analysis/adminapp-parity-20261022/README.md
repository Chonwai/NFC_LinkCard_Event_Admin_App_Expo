## 最該知道的三件事

### 1. 有一顆按鈕按了幾個月都是 404

`POST /registrations/checkin/override` **後端從來沒有這條路由**。
現場人員每次按「申請主管覆核」就是一條必死的請求，畫面回的還是同一個
「尚未就緒」橫幅。

**近似的 `/status` 不能頂替**：它對已 `CHECKED_IN` 的紀錄回
`409 REGISTRATION_STATUS_UNCHANGED`（後端明文拒絕無意義寫入），而且需要
COORDINATOR 以上權限——不是閘口的 OPERATOR。

處置：移除按鈕，改指詳情頁（那裡看得到報到時間）。見 `03-semantic-drift.md` §S-1。

### 2. 錢包帳本一直在說謊

後端的交易投影是 `id / type / amount / balanceAfter / description / sourceType /
createdAt`——**沒有 `approvedBy`**。App 的型別宣告了它，UI 也照著渲染：

```tsx
label={`${tx.type} · ${tx.approvedBy ?? "—"}`}   // 每一行都顯示「—」
```

看起來像「沒有人員記錄」，實際上是「這個欄位不存在」。
同時忽略分頁 ⇒ **超過 20 筆的流水永遠看不到，也沒有任何提示**。

### 3. 現在有 CI 閘門了

`npm run check:contract` 比對 App 呼叫與後端路由快照，已接進
`.github/workflows/ci.yml`。它有自己的**負向測試**（把死路由塞回去必須失敗）——
一個永遠會過的檢查比沒有檢查更糟。

而 3 個缺口也不是「Web 有所以也要有」——是**五家競品都放在現場**的能力。
