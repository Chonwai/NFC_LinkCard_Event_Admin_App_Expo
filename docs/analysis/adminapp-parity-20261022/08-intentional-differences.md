# 08 — 刻意差異登記簿（Intentional Difference Register）

**這份檔案的目的只有一個：讓「為什麼 App 沒有這個功能」有唯一答案，不必每季重新辯論。**

使用規則：

- 任何被問到「App 為什麼沒有 X」時，先查這裡。
- 每一條都要有 **理由** 與 **產業證據**（見 `05-industry-research.md`）。
- 每一條都要有 **「什麼情況該重新考慮」**，否則它會變成永久的藉口。
- 要新增能力時，是「改這份檔案」，不是「偷偷做掉」。

判定基準：**這個能力屬於「活動現場、手機、工作人員、30 秒內完成」嗎？**
是 → 應該在 App；否 → 留在 Web 並登記於此。

---

## ID-01 — 活動 Profile 編輯

| 欄位       | 內容                                           |
| ---------- | ---------------------------------------------- |
| 能力       | 編輯活動名稱、時間、地點、描述、主視覺         |
| 在 Web     | `app/(event)/manage/[eventId]/profile`         |
| App        | 無                                             |
| 理由       | 設定層。低頻、高風險、需要完整表單與驗證。     |
| 產業       | 六家全部留在 Web（R1 §5「設定層」）            |
| 重新考慮若 | 現場需要臨時改「今日開放入場時間」這類單一欄位 |

## ID-02 — 活動頁面內容編排（Card / Section CMS）

| 欄位       | 內容                                                     |
| ---------- | -------------------------------------------------------- |
| 能力       | 活動首頁的卡片與段落編排、排序、圖片上傳                 |
| 在 Web     | `app/(event)/manage/[eventId]/content`                   |
| App        | 無                                                       |
| 理由       | 內容層。需要拖拉排序與圖片裁切，手機不是合適的編輯介面。 |
| 產業       | Whova 的 Content／Agenda Center 在 Web（R1 §5）          |
| 重新考慮若 | 現場需要上傳活動即時照片到活動頁                         |

## ID-03 — 票種管理（CRUD）

| 欄位       | 內容                                                             |
| ---------- | ---------------------------------------------------------------- |
| 能力       | 建立／修改／停用票種、價格、名額、報名表單欄位                   |
| 在 Web     | `app/(event)/manage/[eventId]/ticket-types`                      |
| App        | 只**讀**（`GET /ticket-types`，供現場報名選票種）                |
| 理由       | 設定層。改價格與名額是財務／法務敏感操作。                       |
| 產業       | Eventbrite 的票種與報名表單設定在 Web（R1 §3a 引其 help centre） |
| 重新考慮若 | 現場需要「臨時加開一個現場票種」——目前必須回 Web                 |

## ID-04 — 參展商管理與匯入

| 欄位       | 內容                                                                                                            |
| ---------- | --------------------------------------------------------------------------------------------------------------- |
| 能力       | 參展商 CRUD、攤位、公司頁、成員、CSV 匯入                                                                       |
| 在 Web     | `app/(event)/manage/[eventId]/exhibitors`（+`/import`）                                                         |
| App        | 無                                                                                                              |
| 理由       | 內容層 + 銷售 + 權限。                                                                                          |
| 產業       | **六家無一**把 organizer 視角的 exhibitor 管理放進門側 App（R1 §3b）；mobile 只做 exhibitor 自己的 lead capture |
| 重新考慮若 | 現場需要掃參展商 badge 收集 leads（那是 exhibitor 視角，不是 organizer）                                        |

## ID-05 — 議程／Session 建立與編輯

| 欄位       | 內容                                                             |
| ---------- | ---------------------------------------------------------------- |
| 能力       | 建立場次、指派講者、設定容量、時間                               |
| 在 Web     | `app/(event)/manage/[eventId]/sessions`（+2 子頁）               |
| App        | 無                                                               |
| 理由       | 內容層。                                                         |
| 產業       | 六家的 session **建立**全在 Web（R1 §3c）                        |
| 重新考慮若 | **不需要重新考慮「建立」；但「現場報到」是另一個問題，見 ID-06** |

## ID-06 — ⚠️ Session 現場報到（**不是**刻意差異，是缺口）

| 欄位   | 內容                                                                                                           |
| ------ | -------------------------------------------------------------------------------------------------------------- |
| 能力   | 掃參加者進某一場次、計容量、記錄出席                                                                           |
| 在 Web | 有（`sessions/[sessionId]/registrations`）                                                                     |
| App    | **無**                                                                                                         |
| 理由   | 這是**現場執行層**，符合「App 應該有」的判定。                                                                 |
| 產業   | Cvent（OnArrival）、Whova（Admin Tools）、zkipster（Sessions tab）、Swapcard（SwapAccess）、Expo Pass 全部都有 |
| 狀態   | 列入 `04-sync-plan.md` N3，≈2 人日 `(估)`，後端 `POST /sessions/:sessionId/checkin` 已就緒                     |

> 這一條刻意留在登記簿裡，但標成「缺口」——登記簿不能只放對自己有利的條目。

## ID-07 — 投票 / Polls

| 欄位       | 內容                                                                                    |
| ---------- | --------------------------------------------------------------------------------------- |
| 能力       | 建立題目、選項、啟用／關閉、看結果                                                      |
| 在 Web     | `app/(event)/manage/[eventId]/polls`                                                    |
| App        | 無                                                                                      |
| 理由       | 內容層 + live interaction；建立需要題目／選項／可見性／時長。                           |
| 產業       | Swapcard 明文「polls 建立與管理 exclusively on the web version」（R1 §3d）              |
| 重新考慮若 | 需要在 session 現場由主持人即時開關 poll（Whova 允許講者從手機建 poll，是業界唯一例外） |

## ID-08 — 銀行匯款核銷

| 欄位       | 內容                                                                 |
| ---------- | -------------------------------------------------------------------- |
| 能力       | 檢視匯款證明、核准／駁回                                             |
| 在 Web     | `app/(event)/manage/[eventId]/bank-transfers`                        |
| App        | 無                                                                   |
| 理由       | 財務層。需要看圖檔、對帳、留稽核軌跡。                               |
| 產業       | 六家均未見門側 App 做匯款核銷 `(推論，R1 §6)`                        |
| 重新考慮若 | 現場收現金需要「即時標記已收款」——那是 `wallet/top-up`，不是匯款核銷 |

## ID-09 — 組織角色管理

| 欄位       | 內容                                                         |
| ---------- | ------------------------------------------------------------ |
| 能力       | 邀請／移除 SUPER_ADMIN、COORDINATOR、OPERATOR                |
| 在 Web     | `app/(event)/manage/[eventId]/org-roles`                     |
| App        | 無（但**讀**角色：`my-access`、`my-managed._meta.userRole`） |
| 理由       | 權限層。自我授權是最危險的操作。                             |
| 產業       | zkipster 的權限在 Account Settings（R1 §6）                  |
| 重新考慮若 | 幾乎不該                                                     |

## ID-10 — 活動 Settings

| 欄位       | 內容                                                   |
| ---------- | ------------------------------------------------------ |
| 能力       | 活動狀態、發布、報名開關、通知設定                     |
| 在 Web     | `app/(event)/manage/[eventId]/settings`                |
| App        | 無                                                     |
| 理由       | 設定層。                                               |
| 產業       | Expo Pass 的 kiosk 權限要在 Event Settings 開（R1 §6） |
| 重新考慮若 | 現場需要「緊急關閉報名」的單一開關                     |

## ID-11 — 完整報名資料編輯

| 欄位   | 內容                                                                                                                                    |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| 能力   | 修改姓名、Email、公司、自訂欄位                                                                                                         |
| 在 Web | `app/(event)/manage/[eventId]/registrations`（drawer）                                                                                  |
| App    | **完全沒有**（只有查詢）                                                                                                                |
| 理由   | 目前沒有 `PATCH /registrations/:id` 端點，要先有後端能力。                                                                              |
| 產業   | **偏保守**：Cvent 正面允許（desktop/phone/tablet）、Expo Pass 條件允許（Web 開權限 + passcode）、zkipster 可新增賓客；Eventbrite 禁止。 |
| 狀態   | 建議做「有限欄位 + 權限旗標 + 審計」，見 `04-sync-plan.md` N4（需產品決策）                                                             |

## ID-12 — Badge 現場列印

| 欄位       | 內容                                                                                    |
| ---------- | --------------------------------------------------------------------------------------- |
| 能力       | 現場即時列印名牌                                                                        |
| 在 Web     | 無（Web 只有 badge 庫存與 CSV 匯出）                                                    |
| App        | 無                                                                                      |
| 理由       | 需要印表機整合，屬於硬體課題。                                                          |
| 產業       | Cvent 的 on-demand badge printing、zkipster 的現場列印、Expo Pass 的 kiosk 都是核心能力 |
| 重新考慮若 | 活動規模大到需要現場補印（目前流程是事前印好）                                          |

## ID-13 — NFC 寫卡 / 讀卡 / 名片交換（**App 獨有**）

| 欄位   | 內容                                                                      |
| ------ | ------------------------------------------------------------------------- |
| 能力   | 以 Android 手機寫入 NDEF、讀取 tagUid、兩張卡交換                         |
| 在 Web | **結構性不可能**（瀏覽器沒有 `NDEFReader`；已用 grep 驗證零命中）         |
| App    | 有                                                                        |
| 理由   | 硬體能力。                                                                |
| 產業   | **不尋常**：六家公開文件都以 QR／barcode 為主（R1 §6）                    |
| 意義   | 這是 **LinkCard 的差異化**，不是缺口；應以 capability flag 與契約測試保護 |

## ID-14 — 現場報名（Walk-in）（**App 獨有**）

| 欄位   | 內容                                                               |
| ------ | ------------------------------------------------------------------ |
| 能力   | 現場選票種、填個資、同意書、建立報名                               |
| 在 Web | **沒有**（Web 只有公開報名頁 `/events/:id/register`）              |
| App    | 有                                                                 |
| 理由   | 現場執行層；Web 的報名頁是「參加者自己填」，不是「工作人員代填」。 |
| 產業   | Cvent OnArrival 有 walk-in 報名（R1 §1 表）                        |
| 意義   | 與業界一致，且 Web 沒有等價物——這是 App 的價值所在                 |

## ID-15 — Token 帳本查詢（**App 獨有**）

| 欄位   | 內容                                                                            |
| ------ | ------------------------------------------------------------------------------- |
| 能力   | 查單一參加者的錢包流水                                                          |
| 在 Web | 只有參加者自己的 `/my-tickets/[registrationId]/wallet`；**沒有主辦方視角**      |
| App    | 有（`registrant/[id]`）                                                         |
| 理由   | 現場要能回答「我還有多少點數」。                                                |
| 產業   | 超出 Cvent／Expo Pass／zkipster 公開範圍 `(推論，R1 §6)`                        |
| 意義   | 差異化；但**沒有活動層級彙總**（後端沒有這個端點），所以 `token.tsx` 只能是入口 |

## 統計

| 類別                                 | 條數 | ID                            |
| ------------------------------------ | ---- | ----------------------------- |
| 刻意差異（設定／內容／財務／權限層） | 9    | ID-01,02,03,04,05,07,08,09,10 |
| **缺口**（現場執行層，應該補）       | 3    | ID-06, ID-11, ID-12           |
| 差異化（App 獨有）                   | 3    | ID-13, ID-14, ID-15           |

> 9 : 3 的比例就是本文對「功能是否完全一致」的回答：
> **大部分不同是對的，少數不同是缺的。**
