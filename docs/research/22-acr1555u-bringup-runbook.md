### ❌ 為什麼 Android EVK 不能用

我解開了 `acsbt-1.0.1.aar`，裏面**只有兩個 reader class**：

```
com/acs/bluetooth/Acr1255uj1Reader     ← ACR1255U-J1
com/acs/bluetooth/Acr3901us1Reader     ← ACR3901U-S1 / ACR3901T-W1
```

**沒有 `Acr1555uReader`。** 它自己的 `ReadMe.txt` 也寫明支援
「ACR3901U-S1, ACR3901T-W1, and ACR1255U-J1」——這是 **2018 年**的建置，
那時 ACR1555U 還沒出。

⇒ 你若照我上一輪寫的「先跑 `BTDemo-1.0.1.apk`」，會卡在「偵測不到讀卡機」，
然後浪費時間查藍牙。**這不是你的問題，是工具版本的問題。**

### ✅ 那要用哪個？

ACS 驅動頁上有兩個不同的 Android 套件，要選**新的那個**：

| 套件                              | 版本       | 日期           | 用途                         |
| --------------------------------- | ---------- | -------------- | ---------------------------- |
| Android EVK（USB）                | v1.1.8     | 2025-11-25     | USB OTG 走 CCID              |
| **Android BLE EVK (SmartCardIO)** | **v0.6.2** | **2025-12-03** | **BLE APDU 透傳 ← 你要這個** |
| iOS BLE EVK (SmartCardIO)         | v0.7.0     | 2026-07-27     | iOS                          |

下載位置：<https://www.acs.com.hk/en/driver/622/acr1555u-secure-bluetooth%C2%AE-nfc-reader/>

## 1. 硬體準備（10 分鐘）

### 1.1 讀卡機進入 BLE 可被搜尋狀態

```
長按電源鍵 3 秒  →  綠燈亮
                  →  藍燈「閃爍」= 可被搜尋 ✅
                  →  藍燈「長亮」= 已被某台裝置連線 ⚠️
```

若綠燈亮但**藍燈不閃**：再長按 **MODE 鍵 3 秒**。
若藍燈長亮（可能是你的筆電佔住了）：長按 **MODE 鍵約 4 秒**清除綁定。

### 1.2 平板端

| 設定                   | 為什麼                                              |
| ---------------------- | --------------------------------------------------- |
| 藍牙 **開**            | 基本                                                |
| **定位（Location）開** | Android 把 BLE 掃描歸類為可能洩漏位置，關掉會掃不到 |

### 1.3 讀卡機接法

讀卡機是 **USB Type-C**，且有**內建充電電池** ⇒ 用 BLE 時不用插線，
不會吸平板電。

## 2. 官方 demo 驗證（1 小時）— **這是分水嶺**

目標：用**原廠自己的工具與金鑰**證明「平板 → 讀卡機 → 認證 → 讀卡」這條鏈是通的。
這一步**零風險**（金鑰是對的，不會扣錯誤額度）。

### 2.1 安裝

1. 下載 **Android BLE EVK (SmartCardIO) v0.6.2**
2. 把裏面的 demo APK 傳到平板安裝
3. 開啟時會要求硬體控制權限 → 允許

### 2.2 連線與認證

| 步驟           | 預期結果                            |
| -------------- | ----------------------------------- |
| 掃描裝置       | 清單出現你的 ACR1555U               |
| 點選連線       | 顯示 connected / ATR 或 card status |
| 執行認證       | 成功，無錯誤                        |
| 把卡放上感應區 | 讀到 UID                            |

### 2.3 ⭐ 順便做這件事：讀錯誤計數器

demo 通常有「APDU」或「Escape」輸入欄，讓你可以送自訂指令。
**送這一個**（純讀取，不會扣額度）：

```
E0 00 00 72 00
```

| 回應                 | 意思                                 |
| -------------------- | ------------------------------------ |
| `E1 00 00 00 01 00`  | ✅ 錯誤計數 = 0，額度全滿            |
| `E1 00 00 00 01 <n>` | ⚠️ 已經錯了 n 次。**先查原因再繼續** |

**把這個數字記下來**，它是後面所有測試的基線。

> 若 demo 沒有 APDU 輸入欄，跳到 §3——網頁探測器會用另一條路徑量測。

### 2.4 這一步的四種結果

| 結果                     | 意思                         | 下一步                                     |
| ------------------------ | ---------------------------- | ------------------------------------------ |
| 全部成功                 | ✅ 硬體鏈沒問題              | 進 §3（網頁）或 §4（App）                  |
| 掃不到裝置               | BLE 沒進可搜尋狀態，或被佔住 | 回 §1.1                                    |
| 連上但認證失敗           | 金鑰不對或型號不對           | 確認 APK 版本是 ACR1555U 對應的那個        |
| 連上、認證成功、讀不到卡 | 卡片太遠或不是 NTAG          | 貼緊感應區再試；確認卡片是 NTAG213/215/216 |

## 3. 網頁測試（你要的「在前端 website 上測試」）

### 3.1 先說清楚現在能做什麼、不能做什麼

| 能力                                                  | 現在                     | 原因           |
| ----------------------------------------------------- | ------------------------ | -------------- |
| 連線 + 列出 GATT                                      | ✅ **現在就能**          | 純讀取，零風險 |
| 讀 UID / 讀寫卡片                                     | ⬜ 需先確認 service UUID | 見下           |
| 在現有 `/check-in/[eventId]/nfc` 加「讀卡機讀取」按鈕 | ⬜ 要等上一步            | 先把輸入源搞定 |

### 3.2 用探測器（已放在 repo）

工具：`tools/nfc-web-probe/probe.html`（說明見同資料夾 `README.md`）

**它在做什麼**：連上讀卡機 → 列出所有 service 與 characteristic → 印出來。
**它不做什麼**：不認證、不寫卡、不送任何自組訊框 ⇒ **不可能消耗錯誤額度**。

#### 平板怎麼開（Web Bluetooth 必須 HTTPS）

| 做法                                            | 時間   | 備註                  |
| ----------------------------------------------- | ------ | --------------------- |
| 拖到 **Cloudflare Pages / Netlify Drop**        | 2 分鐘 | 最快，取得 HTTPS 網址 |
| `python3 -m http.server` + `cloudflared tunnel` | 5 分鐘 | 不部署                |
| 放進前端 `public/`                              | 2 分鐘 | ⚠️ 會上生產，測完刪   |

#### 操作與判讀

1. 讀卡機進 BLE 模式（藍燈閃）
2. 開頁面 → **「1. 搜尋並連線讀卡機」** → 選裝置
3. **「2. 列出所有 service 與 characteristic」**
4. 把輸出**複製保存**

| 看到什麼                                      | 意思                                                               |
| --------------------------------------------- | ------------------------------------------------------------------ |
| `▸ SERVICE 00003970-…` + 三條 characteristic  | ✅ **service UUID 確認**，可以進 §3.3                              |
| 一個 service 都沒找到                         | service UUID 不是 `3970`。把 `CANDIDATE_SERVICES` 加上其他候選再試 |
| `3971` 顯示 `[write]`、`3972` 顯示 `[notify]` | ✅ 與手冊一致，pipe 方向確認                                       |
| 斷線後按「3. 重新連線」失敗                   | ⚠️ U3 的答案就是「不能」，現場要改用別的裝置                       |

### 3.3 為什麼不直接寫一個能寫卡的網頁

因為**傳輸框架（framing）我們還不確定**。

原廠手冊 §5.2.3 的 checksum 說明寫「XOR of Slot, Len, **Frame Type**, Host & Reader
Seq, Data」，但表格裏列的欄位叫 **Reserved**——兩個名字指同一個位元組，但不確定。
**這個位元組算錯，整個訊框會被丟棄**，而且你不會知道是算錯還是別的錯。

而官方 SDK 的框架實作**包在閉源的 `acsbt-1.0.1.aar` 裏**，看不到原始碼。

⇒ 所以正確順序是：**先拿到一次真實成功的訊框長什麼樣**，再自己實作。
那可以從 §2 的 demo app 觀察，或從 §3.2 探測器確認 pipe 之後，
用一個「送單一 framed 指令並印出回應」的小實驗取得。

### 3.4 現有網頁已經有的東西（不用重做）

`LinkCard_Frontend/app/check-in/[eventId]/nfc/page.tsx` 已經有：

- `tagUid` 文字輸入框（`:121-124`）
- `POST /nfc/bind` 接線
- 錯誤處理（`BADGE_ALREADY_BOUND` 等）

⇒ 網頁端**只缺「把 tagUid 從讀卡機填進去」這一段**。
一旦 §3.2 確認 service UUID，這就是一個小改動，不是新功能。

## 6. 絕對不要做的事
