## 2. 依賴關係（關鍵路徑）

```
W1: Credential 模型 (F-06) ──→ W2: 名單 search API (F-03)
                                  ↓
W2: 掃碼簽到三態 (F-01) ←── 簽到 API（既有）
W2: Token 櫃台 (F-02) ←── v11.3 P0-05 路由（8 條）
W3: 四大功能卡 (F-04) ←── F-01/02/03 完成
W4: 用戶詳情 (F-05) ←── F-02/03 完成
W5: 真機 E2E (F-09) ←── 全部 P0 完成
```

**關鍵路徑**：Credential 模型 → search API → 名單列表 → 四大功能卡 → 用戶詳情 → E2E。
**瓶頸**：Credential 模型（F-06）是架構地基，**必須 W1 先做**，否則 F-03/04/05 後續重工。

## 4. MVP 底線（若時間不夠只保這些）

**會議 MVP**：掃碼簽到 + Token 增扣 + 名單查詢 + Email 自動建帳。
**可捨棄**：儀表板、工作人員權限分層、NFC（降級 QR 手帶）。

**對應到本清單**：

- ✅ 保留：F-01（掃碼簽到）、F-02（Token 櫃台）、F-03（名單查詢）
- 🔴 需後端：Email 自動建帳（會議待辦 1）
- ❌ 可捨棄：P-03（權限分層 → 共用帳號）、P-04（儀表板）、NFC 部分
