# LinkCard Event Admin App — 功能開發清單（會議整合 + 藍圖）

> 產出：Neo Loop Engine（JARVIS Agent Network）｜2026-09-15
> 品質合約：strict（threshold 93）/ L3 Deep Dive
> 研究輸入：① 20260914 Meeting 1 深度需求整理（本週會議）② Token v11.3 設計規劃（`04-design-plan.md` R3 PASS 93.00）③ 交接前開發藍圖（`05-handover-blueprint.md`）
> 目標：**整合三個來源，產出 Admin App 的完整功能開發清單**，供 11 月 Macau Startup Festival MVP 排期參考

---

## 執行摘要（TL;DR）

1. **會議紀錄的 7 大模組中，4 個已有既有資產**（可大幅降低開發成本）：模組 A QR 簽到（Admin App `check-in.tsx` 已有）、模組 B Token 管理（**Token v11.3 已完整設計**，含 `wallet-counter` 畫面規格 §5.2）、模組 C NFC 綁定（`nfc-bind.tsx` 已有骨架）、模組 D 名單（`event.service.getRegistrations` 已存在）。
2. **核心增量**：會議紀錄新增了「Token 現場櫃台」、「簽到三態回饋 + 重複覆核」、「四大功能卡首頁」、「用戶詳情頁」、「現場補報名」等**尚未開發**的功能模組——這是本清單的重點。
3. **MVP 生命線**（若時間不夠只保這些）：**掃碼簽到 + Token 增扣 + 名單查詢 + Email 自動建帳**。此與 Token v11.3 的 P0-09（wallet-counter）完全互補。

---

## 整合方法（三來源 → 一清單）

```
來源 1：20260914 Meeting 1（業務需求，本週會議）
   └─ 7 大模組（A-QR簽到 / B-Token / C-NFC / D-名單 / E-憑證 / F-權限 / G-儀表板）
        + 頁面清單（12 頁）+ 非功能需求 + 待決策 7 項 + 排期 + UAT
來源 2：Token v11.3 設計規劃（2026-09-14，R3 PASS）
   └─ P0-09 wallet-counter 畫面規格（§5.2）+ 8 條新路由 + 權限 + 冪等 + SOP（§5.3）
來源 3：交接前開發藍圖（2026-09-14）
   └─ Web vs App 差距矩陣 + 15 項未開發功能 + 4 個 Sprint + 關鍵發現
        +【新增】backbone 審計 + EAS/Deploy 空缺
整合 → 本清單（差異分析表 + 功能開發清單 + MVP 排期 + 依賴/風險）
```

**關鍵原則**：**不重複規劃已設計好的東西**。Token v11.3 的 `wallet-counter` 已是完整施工圖，本清單直接引用其規格（§5.2），不再重畫；本清單聚焦於**會議紀錄新增、但兩個既有資產都沒涵蓋**的功能（三態簽到增強、四大功能卡、用戶詳情、現場補報名、工作人員權限、儀表板、多語言葡文、安全/稽核）。

## 三來源覆蓋矩陣（會議 vs 既有資產）

| 會議模組               | Token v11.3                                  | 交接藍圖                   | Admin App 現況       | 判定                          |
| ---------------------- | -------------------------------------------- | -------------------------- | -------------------- | ----------------------------- |
| **A. QR 簽到**         | 未涵蓋                                       | 已做（check-in.tsx）       | ✅ 基本版有          | 🟡 需增強（三態/覆核/計數器） |
| **B. Token 管理**      | ✅ **§5.2 wallet-counter 完整規格**（P0-09） | 未涵蓋                     | ❌ 無                | 🟢 有施工圖，直接引用         |
| **C. NFC 綁定**        | OOS（tap-to-deduct 不做）                    | 已做（nfc-bind.tsx）       | ✅ 骨架有            | 🟡 需補發/換卡/退卡           |
| **D. 名單/搜尋**       | 未涵蓋                                       | 已排（Registrations 列表） | 🟡 service 有、UI 無 | 🟡 需建列表頁                 |
| **E. 憑證 Admin 視角** | 未涵蓋                                       | 未涵蓋                     | ❌ 無                | 🔴 新需求                     |
| **F. 工作人員權限**    | 權限收緊（P0-04）                            | 已排（角色門控）           | ❌ 無                | 🟡 需建                       |
| **G. 儀表板**          | 對帳報告（P0-06）                            | 未涵蓋                     | ❌ 無                | 🔴 新需求（現場版）           |
| 頁面清單（12 頁）      | wallet-counter                               | Registrations/settings     | 已有 6 頁            | 整合下節                      |
| 非功能需求             | 部分（冪等/稽核）                            | —                          | —                    | 需補（見 §五）                |
| 待決策 7 項            | D1-D15                                       | —                          | —                    | 對齊（見 §七）                |

> **結論**：會議紀錄覆蓋「現場作戰」完整需求；Token v11.3 提供「帳務引擎」施工圖；交接藍圖提供「App 骨架」現況。三者互補，無重大衝突。
